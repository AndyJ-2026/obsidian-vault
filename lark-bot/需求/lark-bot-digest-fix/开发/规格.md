# 消息分析修复与增强 规格

## 模块一：parse_ai JSON 解析修复

### 功能描述
AI 模型有时不严格遵守"只输出 JSON"的指令，会在 JSON 前后加解释文字。需要从混合文本中可靠提取 JSON。

### 输入/输出
- 输入：AI 返回的原始字符串，可能的形式：
  - 纯 JSON：`{"reply": "...", "action": "...", "params": {}}`
  - 前缀文字 + JSON：`我来帮你查一下。\n{"reply": "...", ...}`
  - markdown 包裹：`` ```json\n{...}\n``` ``（已有处理）
- 输出：解析后的 dict，包含 reply / action / params

### 约束与边界条件
- 优先尝试整体 `json.loads`（现有行为，覆盖模型正确输出的情况）
- 失败时用正则从文本中提取第一个 `{...}` JSON 对象
- 提取也失败时，走现有 fallback（raw 文本当 reply，action=none）

### 验收标准
- [ ] 纯 JSON 输入正常解析（不退化）
- [ ] `"解释文字\n{\"reply\":\"x\",\"action\":\"digest\",\"params\":{}}"` 能正确提取 action=digest
- [ ] 完全非 JSON 输入仍走 fallback，不报错

## 模块二：digest 消息拉取字段修复

### 功能描述
`do_digest` 和 `send_daily_report` 中从 API 返回数据读取消息内容的字段路径错误。

### 输入/输出
- lark-cli 实际返回格式：
  ```json
  {
    "content": "消息正文",
    "sender": {"name": "Mei Fang", "id": "ou_xxx", "sender_type": "user"}
  }
  ```
- 当前代码用 `m.get("body",{}).get("content","")` → 永远空字符串
- 当前代码用 `m.get("sender",{}).get("id","?")` 做发送人 → 没有名字，不可读

### 修复内容
- 消息内容：`m.get("body",{}).get("content","")` → `m.get("content","")`
- 发送人名字：`m.get("sender",{}).get("id","?")` → `m.get("sender",{}).get("name","未知")`
- 同样修复 `send_daily_report` 中的相同问题

### 验收标准
- [ ] digest 能拉到群里的实际消息内容
- [ ] 汇总结果中显示发送人名字而非 ID
- [ ] 日报功能同样能正确读取消息

## 模块三：digest 定向分析增强

### 功能描述
当前 digest 只做"与 Jake 相关的通用汇总"。需要支持用户提出个性化分析请求，例如：
- "帮我看看 meifang 提了什么需求"
- "分析一下远程 trigger 发出来的内容"
- "最近有没有人提到 HOOK 代币"

### 输入/输出
- REPLY_PROMPT 中 digest action 增加可选 params：
  - `query`：用户原始问题（透传给汇总 AI，让它做针对性分析）
  - `days`：时间范围天数（AI 根据问题上下文推断，默认 7）
- do_digest 接收 query + days 参数，改变行为：
  - 有 query（定向分析）→ 拉取当前群（chat_id）的消息，不做 Jake 过滤，把原始问题 + 消息列表交给 AI 做定向分析
  - 无 query（通用汇总）→ 拉全部群、Jake 过滤、2 天范围、通用汇总

### DIGEST_PROMPT 改造
- 现有 prompt 硬编码"与 Jake 相关"→ 保留给无 query 的通用汇总
- 新增 ANALYSIS_PROMPT：把用户问题作为分析指令，消息列表作为上下文，让 AI 做针对性回答

### 消息拉取策略

| 场景 | 时间范围 | 消息量 | 群范围 |
|------|----------|--------|--------|
| 日报（20:00 定时） | 当天 0 点至今 | `--page-all` 全量 | 所有群 |
| 通用汇总（"汇总一下"） | 最近 2 天 | `--page-all` 全量 | 所有群 |
| 定向分析（带 query） | AI 推断 days，默认 7 天 | `--page-all` 全量 | 当前群 |

### 约束与边界条件
- 使用 `--page-all` 替代硬编码 `--page-size 50`，在时间范围内拉全量
- 机器人自己发的消息也要包含（trigger 预警内容就是机器人发的）
- 不过滤 sender_type，user 和 bot 消息都保留

### 验收标准
- [ ] "@bot 汇总一下" → 走原有全群 Jake 相关汇总（不退化）
- [ ] "@bot 帮我看看 meifang 提了什么需求" → 只分析当前群，days=7，返回 meifang 相关内容
- [ ] "@bot 分析一下 trigger 发的内容" → 能把机器人发的预警卡片内容也纳入分析
- [ ] 日报拉取范围改为当天 0 点至今
