# 规格

## 整体流程

```
用户在飞书私聊 Bot："帮我转写这个会议"
  → Bot 启动本地录音（ScreenCaptureKit 捕获系统音频）
  → 用户正常参加飞书会议
  → 会议结束，用户告诉 Bot "结束" 或手动 Ctrl+C
  → Qwen3-ASR (1.7B) 离线转写
  → AI 生成结构化会议纪要
  → 纪要保存为 Obsidian Markdown（会议纪要/）
  → lark-cli docs +create --markdown 上传为飞书云文档
  → lark-cli im +messages-send 私聊发给用户：
      - 一段概括会议主题的文字
      - 云文档链接
  → 删除临时音频文件
```

## 模块拆分

### 模块 1：录音控制

**触发**：用户在飞书私聊 @Bot "帮我转写"
**行为**：
- Bot 调用本地 `meeting start`（复用 Meeting CLI 的 ScreenCaptureKit 录音）
- 录音输出为 PCM/WAV 临时文件
- 用户说"结束"或发送停止指令 → Bot 停止录音

**约束**：
- 只能录制本机参加的会议（系统音频）
- 同一时间只能有一个录音任务

### 模块 2：离线转写

**输入**：录音文件（PCM 16kHz mono）
**引擎**：Qwen3-ASR 1.7B（替换现有 Paraformer-large）
**输出**：带时间戳的转写文本
**约束**：
- M4 16GB 可运行，预计占用 4-5GB 内存
- 离线处理，不要求实时

### 模块 3：纪要生成

**输入**：转写文本
**处理**：AI（MiniMax 或 Claude）生成结构化纪要
**输出格式**：Markdown，包含：
- 会议主题
- 参会人（如能识别）
- 关键讨论点
- 决议/Action Items
- 完整转写记录（折叠）

### 模块 4：输出与分发

**步骤**：
1. 纪要 Markdown 保存到 Obsidian `会议纪要/` 目录
2. `lark-cli docs +create --markdown <file> --title "会议纪要-<日期>-<主题>"` 创建飞书云文档
3. `lark-cli im +messages-send --user-id <jake> --markdown "..."` 私聊发送：
   - 第一段：会议主题概括（纯文字）
   - 第二段：云文档链接
4. 删除临时音频文件

## 技术选型

| 组件 | 方案 |
|------|------|
| 录音 | Meeting CLI（ScreenCaptureKit） |
| ASR | Qwen3-ASR 1.7B |
| 纪要 AI | MiniMax M2.5（现有）或 Claude |
| 文档上传 | lark-cli docs +create --markdown |
| 消息发送 | lark-cli im +messages-send |
| 纪要存储 | Obsidian 会议纪要/ + 飞书云文档 |
