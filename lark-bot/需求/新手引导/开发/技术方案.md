# 技术方案

## 现有架构

```
bot.py（单文件）
  ├─ 硬编码：JAKE_OPEN_ID, "Jake R", "小J" 散落在 prompt 和逻辑中
  ├─ process_event()：p2p 只允许 Jake，group 需 @bot
  ├─ help 命令：纯文本输出
  └─ 无配置文件，无用户状态管理
```

## 改动方案

### 1. 新增 config.json 机制

**文件**：`config.json`（运行时生成，.gitignore 忽略）
**模板**：`config.example.json`（提交到仓库）

```json
{
  "bot_name": "",
  "owner_name": "",
  "owner_open_id": "",
  "llm_base_url": "https://api.minimaxi.com/v1",
  "llm_model": "MiniMax-M2.5"
}
```

**加载逻辑**：
```python
CONFIG_FILE = os.path.join(BOT_DIR, "config.json")

def load_config():
    if os.path.exists(CONFIG_FILE):
        with open(CONFIG_FILE) as f:
            return json.load(f)
    return None

def save_config(cfg):
    with open(CONFIG_FILE, "w") as f:
        json.dump(cfg, f, indent=2, ensure_ascii=False)

CONFIG = load_config()
```

### 2. 配置模式（无 config.json 时）

bot.py 启动时检测 config.json 是否存在：
- 不存在 → 进入配置模式
- 存在 → 正常模式

**配置模式不需要 LLM**，用硬编码对话流程：

```python
# 配置阶段状态机
_setup_state = {
    "step": "init",  # init → wait_bot_name → wait_api_key → done
    "owner_open_id": "",
    "owner_name": "",
    "bot_name": "",
}
```

**流程**：
```
step=init:
  收到第一条 p2p 消息
  → 记录 sender_id 为 owner
  → 通过 lark-cli contact 获取用户姓名
  → 回复 "你好 {name}！我是你的新助手，你想叫我什么名字？"
  → step=wait_bot_name

step=wait_bot_name:
  收到回复
  → 记录 bot_name
  → 回复 "请发一下大模型 API Key（推荐 MiniMax：https://www.minimax.chat）"
  → step=wait_api_key

step=wait_api_key:
  收到回复
  → 验证 key 格式
  → 写入 config.json + 设置环境变量
  → 重新初始化 LLM 客户端
  → 回复 "配置完成！我叫 {bot_name}，{owner_name} 你好~"
  → 发送快速开始卡片
  → step=done，切换到正常模式
```

### 3. 去硬编码

所有 prompt 和逻辑中的硬编码替换：

```python
BOT_NAME = CONFIG["bot_name"] if CONFIG else "助手"
OWNER_NAME = CONFIG["owner_name"] if CONFIG else ""
OWNER_OPEN_ID = CONFIG["owner_open_id"] if CONFIG else ""
```

**prompt 模板化**：
```python
REPLY_PROMPT = f"""你是 {OWNER_NAME} 的飞书 AI 助手，名叫"{BOT_NAME}"。..."""
```

**消息过滤正则动态生成**：
```python
# 现有：re.search(r"Jake\s*R|JakeR|@Jake", ...)
# 改为：
owner_pattern = re.compile(
    "|".join(re.escape(p) for p in [OWNER_NAME, f"@{OWNER_NAME}"]),
    re.IGNORECASE
)
```

**变量名重命名**：
- `JAKE_OPEN_ID` → `OWNER_OPEN_ID`
- `is_jake` → `is_owner`
- `jake_messages` → `owner_messages`

### 4. 新用户引导

**文件**：`onboarded_users.json`
```json
{"users": ["ou_xxx"]}
```

**逻辑**：在 process_event() 的 p2p 分支中，正常模式下：
```python
if not is_onboarded(sender_id):
    send_welcome_card(chat_id)
    mark_onboarded(sender_id)
    # 继续正常处理消息（不要 return）
```

### 5. 快速开始卡片

**构建函数**：`_build_welcome_card()`
- 列出所有功能 + 状态
- 实时拉取 Bot 已加入的群列表
- 使用 config 变量（bot_name, owner_name）

**触发**：
- 新用户首次私聊（自动，一次）
- help/帮助/你能做什么/你会什么（手动，随时）

### 6. help 命令改造

现有纯文本 help → 改为发送快速开始卡片
触发词扩展：`help` / `帮助` / `你能做什么` / `你会什么`
适用范围：p2p + group @bot
