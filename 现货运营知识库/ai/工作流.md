# 工作流

## 任务分流

用户提出任务时，按以下顺序判断归属：

1. **匹配已有项目的新批次** — 检查任务是否属于 `项目/` 下某个标准化项目的新一轮执行（如"USD1 活动调研"→ 竞品调研/活动创意调研 的新批次）。匹配到则直接进入该项目，走进入检查流程
2. **匹配已有非标项目的新模块** — 检查是否属于某个非标项目下的新模块。匹配到则在该项目下新建模块目录和需求.md
3. **新建项目** — 以上均不匹配时，启动新建引导：
   1. 确认项目名称
   2. 确认项目类型（标准化 / 非标）
   3. 创建目录和 入口.md（`status: 草稿`，`created` 取当天）
   4. 按类型引导下一步：
      - 标准化 → 提示补 `规范.md`
      - 非标 → 提示建模块和 `需求.md`

每一步等用户确认后再继续，不跳步。

## 进入检查

AI 每次进入一个项目，按 入口.md 中的 type 分流：

### 标准化项目

必选文件检查：

| 文件          | 缺失时的动作                  |
| ----------- | ----------------------- |
| 入口.md       | 不可执行，提示用户先建项目入口         |
| 规范.md       | 提示："该项目缺执行规范，先补规范还是跳过？" |
| 需求.md（本次执行） | 提示："本次执行没有需求，请先确认主题和范围" |

通过检查后：

1. **询问参考文档**："有没有飞书参考文档需要我先读取？"
   - 用户提供 → 读取内容 → 将有价值的信息吸收进规范.md（升版本号）→ 不保留链接
   - 用户说没有 → 直接进入执行
   - 规范.md 本身即为唯一执行权威，随每次吸收持续变厚
2. 按规范执行，产出写入本地 `产出.md`（不主动写入飞书）
3. 用户手动将产出复制到飞书后，将飞书链接回填到 需求.md frontmatter

### 非标项目

必选文件检查：

| 文件 | 缺失时的动作 |
|------|-------------|
| 入口.md | 不可执行，提示用户先建项目入口 |
| 需求.md | 提示："该模块缺需求，请先确认需求和目标" |

需求即全部。需要拆步骤时在需求.md 里加 checklist。

通过检查后：

1. **询问参考文档**："有没有飞书参考文档需要我先读取？"
   - 用户提供 → 读取内容 → 将有价值的信息吸收进需求.md 正文 → 不保留链接
   - 用户说没有 → 直接进入执行
2. 产出写入本地对应 .md 文件（不主动写入飞书）
3. 用户手动将产出复制到飞书后，将飞书链接回填需求.md frontmatter

## 关键约束

- 给出最佳方案供审阅，通过审阅前禁止执行
- 每个阶段产出写入对应 .md 文件

## 版本追踪

文档通过 frontmatter 中的 version 追踪变更：

```yaml
# 入口.md / 规范.md / 需求.md
version: 1
```

标准化项目中，规范变更后提示用户：后续执行将使用新版规范。
