# 竞品调研规范

AI 执行竞品调研时按本文档操作。竞品范围见 入口.md。

## 数据采集

### 搜索策略

#### 全量调研（活动创意 / 产品功能）

每个交易所至少两轮搜索：

| 轮次 | 关键词策略 | 说明 |
|------|-----------|------|
| 第一轮 | 中文主题词 + 交易所 site: | 覆盖中文公告 |
| 第二轮 | 英文主题词 + 交易所 site: | 覆盖英文公告 |
| 兜底轮 | 主题词 + 交易所名（无 site:）| 社媒、新闻、KOL |

每次执行前，在需求.md 中列出本次的中英文关键词矩阵。

#### 数据快照（特定产品/事件的快速数据拉取）

按数据点组织搜索，而非按交易所。每个数据点独立一批并行搜索：

| 批次 | 目标数据点 | 关键词策略 |
|------|-----------|-----------|
| 第一批 | 参与规模 | `"participants" "subscribers"` + 产品名 |
| 第二批 | 认购/交易金额 | `"subscription" "$" "million"` + 产品名 |
| 第三批 | 实时价格 | 直接抓聚合站 meta 标签（见下文） |
| 第四批 | 社媒评价 | 产品名 + `review opinion Twitter community` |

优先并行跑所有批次，避免串行浪费轮次。搜索第一轮如果发现某数据点在公开渠道无结果（如参与人数未披露），立即停止追搜，标注为"未公开"并尝试截图或推算。

### 工具降级链

```
Firecrawl Search（首选）
  ↓ 无结果或被拦截
Jina Reader（静态页兜底）
  ↓ 仍失败
Firecrawl Scrape（直接抓取活动页URL）
  ↓ 仍失败
记录为"未获取到数据"，标注原因
```

### 交易所实时行情页特殊处理

交易所的交易页面（如 bitget.com/spot/、gate.com/trade/）实时数据通过 WebSocket 推送，Firecrawl 的 headless browser 即使设置 waitFor 也拿不到（DOM 初始值为占位符 `--`）。

应对策略（按优先级）：

1. **读 meta 标签**：Firecrawl Scrape 返回的 metadata 中 `og:title` / `twitter:title` 通常包含服务端渲染的实时价格（如 `653.86 | PRESPAXUSDT`），可从中提取
2. **第三方聚合站**：CoinMarketCap、CryptoRank、CoinGecko 的价格页 meta 标签或 JSON 提取通常可用
3. **公告/新闻页**：交易所的 /news/、/announcements/ 页面是静态渲染，Firecrawl Scrape 可正常抓取
4. **WebFetch 直抓**：部分聚合站（如 CryptoRank）支持 WebFetch 直接读取

不适用 Firecrawl Scrape 的场景汇总：

| 页面类型 | 原因 | 替代方案 |
|----------|------|---------|
| 交易所行情/交易页 | WebSocket 推送，DOM 无数据 | meta 标签 / 聚合站 |
| Reddit | Firecrawl 不支持 | 搜索摘要兜底 |
| 部分媒体站（beincrypto 等） | 403 反爬 | WebFetch / Jina Reader |

### 地区限制绕过

部分交易所页面（如 Gate Pre-IPOs）对特定地区 IP 不可用。Firecrawl 默认代理 IP 通常在欧美，可能被拦截。

应对策略：
- 使用 `proxy: "stealth"` + `location: {"country": "SG"}` 切换到亚洲节点
- 截图优先：即使页面做了地区限制，先试截图确认是否被拦，再决定是否切代理
- 如果 stealth 代理仍被拦，标注为"地区限制"，不再重试

### 覆盖率要求

采集完成后，入口.md 竞品范围内每家必须为以下之一：
- **有活动**：已采集详情 + 截图
- **确认无活动**：至少两轮搜索无结果，明确标注
- **数据获取失败**：标注原因（反爬/地区限制），列出已尝试路径

## 截图规范

每个有活动的交易所用户全路径截图。

优先级：活动落地页 > 公告页 > 交易页面 > 第三方报道

工具：`Firecrawl Scrape`，`formats: ["screenshot"]`，`waitFor: 5000`
命名：`{交易所}_{活动简称}.png`
截图保存到本地，随产出一起写入 `产出.md`。

### 截图作为数据采集手段

当页面 JS 渲染的数据无法通过文本/JSON 提取时，截图本身就是数据源：
- 交易所活动页面的认购数据（参与人数、认购进度、超额倍数等）往往只在 JS 渲染的 UI 中展示
- 先截图确认页面有哪些字段，再决定是否需要用其他方式补数据
- 截图时注意使用正确的代理和地区设置（见"地区限制绕过"）

## 产出结构

### 活动创意调研

#### 1. 活动结论

横向对比表，每个维度给出最佳实践案例 + 简评：

| 维度 | 关注点 |
|------|--------|
| 准入门槛 | 报名方式、最低交易额、新老用户区分 |
| 社交属性 | 裂变机制、KOL 联动、阵营对决、互赠/分享 |
| 用户触达 | 入口数量、视觉刺激（跑马灯/倒计时/弹窗）、触达频率 |
| 用户留存 | 打卡机制、多期活动、习惯养成设计、LTV 延长策略 |
| 品牌势能 | 活动与品牌形象联动、叙事一致性 |
| 开奖/奖励特色 | 开奖频率、奖品形式（实物/代币/体验金）、确定性 vs 彩票感 |

#### 2. 友商活动概览

逐家深挖，每家统一格式：

| 字段 | 说明 |
|------|------|
| 活动链接 | 原始 URL |
| 活动链路 | 用户从首页到参与的完整路径（入口位置、跳转层级），配截图 |
| 活动机制 | 分活动一/二/...描述规则，含门槛、任务、奖励发放方式 |
| 总奖池 | 金额 + 币种/形式 |
| 时间节点 | 起止时间、是否分期 |
| 活动亮点 | 该活动的核心策略洞察（为什么有效、对用户行为的驱动逻辑） |

每家末尾嵌入截图。

#### 3. 可复用点

分两类输出：

**UI/UX：**
- 视觉刺激元素：中奖名单轮播、开奖倒计时、异型弹窗、奖品估值展示
- 入口设计：有逻辑承接的活动入口就近放置
- 游戏化交互：刮刮乐、盲盒、福卡等

**活动逻辑：**
- 流量承接：活动间的用户流转设计
- 拉新策略：低门槛 / 100% 中奖 / 高频开奖 / 保赔券
- 社交裂变：节日祝福类 / 热点辩论类 / KOL 带队竞赛 / 互赠机制
- 留存设计：每日打卡、多期活动、阶梯任务
- 品牌联动：活动叙事与品牌形象的结合点
- 开奖创新：哈希开奖、实物奖品、阵营对决等差异化形式

### 产品功能调研

#### 1. 数据结论

各家功能横向对比表，维度按主题灵活调整，常见维度：
- 品类数量与覆盖范围
- 费率结构（基础费率、VIP 折扣）
- 规则与门槛
- 收益/APR

#### 2. 梯队分析

按功能深度划分第一/二/三梯队，说明分级依据：
- 第一梯队：全品类覆盖、机制成熟
- 第二梯队：多品类试水、有差异化亮点
- 第三梯队：象征性布局、非战略重点

#### 3. 精进项

结合我方现状，提出可跟进方向（如新品类、费率优化、机制借鉴）。

### 数据快照

适用场景：针对特定产品/事件，快速拉取关键数据点（非全量活动调研）。

#### 1. 核心数据对比表

横向对比各家同一产品的关键指标（参与人数、认购金额、产品机制等）。

#### 2. 实时交易数据

当前价格、24h 量、vs 认购价/发行价。标注数据来源和采集时间。

#### 3. 社媒情绪

正面 / 负面分列，标注来源（Twitter KOL、Reddit、媒体）。

#### 4. 数据缺口说明

标注哪些数据点未获取到、原因、已尝试路径。对未公开数据提供合理推算。

### 周报（活动创意调研）

按活动分类组织（如交易赛、空投、Launchpool、社交裂变等），每类包含：

#### 分类模板

```
## {分类名}

**趋势概述**：本周期该类活动的整体动向（1-2 句）

### {交易所} — {活动名称}
- **活动链接**：{原始 URL，必填}
- **时间**：起止时间
- **机制简述**：核心规则、门槛、奖池（3-5 句）
- **可复用点**：该活动最值得借鉴的 1-2 个点

（同类有多家则逐家列出）

**可行项**：基于本分类活动，我方可落地的行动建议
**讨论点**：需周会讨论决策的问题
```

#### 链接采集要求

- 每个活动案例**必须**附原始活动链接，无链接的案例标注"链接未获取 — {原因}"
- 优先采集活动落地页 URL；落地页不可用时退而使用公告页 URL
- 链接来源：搜索结果直链 > Firecrawl 抓取页的源 URL > 公告中心页

### 竞品基础情报

维护持续更新的对比表，维度：费率结构、拉新机制、VIP体系、现货产品布局。标注每条数据的更新时间。
