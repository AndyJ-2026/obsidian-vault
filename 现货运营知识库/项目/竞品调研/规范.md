# 竞品调研规范

AI 执行竞品调研时按本文档操作。竞品范围见 入口.md。

## 数据采集

### 搜索策略

#### 全量调研（活动创意 / 产品功能）

每个交易所至少两轮搜索：

| 轮次 | 关键词策略 | 说明 |
|------|-----------|------|
| 第一轮 | 中文主题词 + 交易所 site: | 覆盖中文公告 |
| 第二轮 | 英文主题词 + 交易所 site: | 覆盖英文公告 |
| 兜底轮 | 主题词 + 交易所名（无 site:）| 社媒、新闻、KOL |

每次执行前，在需求.md 中列出本次的中英文关键词矩阵。

#### 数据快照（特定产品/事件的快速数据拉取）

按数据点组织搜索，而非按交易所。每个数据点独立一批并行搜索：

| 批次 | 目标数据点 | 关键词策略 |
|------|-----------|-----------|
| 第一批 | 参与规模 | `"participants" "subscribers"` + 产品名 |
| 第二批 | 认购/交易金额 | `"subscription" "$" "million"` + 产品名 |
| 第三批 | 实时价格 | 直接用 CDP 打开交易页或聚合站抓取 |
| 第四批 | 社媒评价 | 产品名 + `review opinion Twitter community` |

优先并行跑所有批次，避免串行浪费轮次。搜索第一轮如果发现某数据点在公开渠道无结果（如参与人数未披露），立即停止追搜，标注为"未公开"并尝试截图或推算。

### 工具选择

根据场景选择最合适的工具，无固定降级链：

| 场景 | 工具 | 说明 |
|------|------|------|
| 搜索发现信息来源 | WebSearch | 关键词搜索，获取摘要和 URL |
| 已知 URL，提取特定信息 | WebFetch / Jina Reader | 静态页内容提取，Jina 省 token |
| 已知 URL，需要原始 HTML | curl | meta 标签、JSON-LD 等结构化字段 |
| JS 渲染页面（活动页、交易页） | CDP 浏览器 | 真实 Chrome 渲染，所有动态内容可见 |
| 需要登录态 / 交互操作 | CDP 浏览器 | 天然携带 Chrome 登录态 |
| 需要截图 | CDP 浏览器 | `/screenshot` 截取真实渲染画面 |
| 反爬严格的站点 | CDP 浏览器 | 真实浏览器指纹，不易被拦截 |

**原则：**
- 简单公开页面用 WebSearch/WebFetch/Jina 即可；活动页、交易页、需要交互或截图的场景直接上 CDP
- **活动中心页必须用 CDP 直接浏览**，不要仅靠 WebSearch 搜新闻稿。多数交易所活动中心对搜索引擎和 WebFetch 有反爬限制（如 Gate 返回 403），CDP 真实浏览器可正常访问
- WebSearch 的作用是**发现线索和补充信息**（如第三方报道、社媒评价），不是采集活动详情的主要手段

### 执行流程

周报类调研的标准执行顺序：

1. **CDP 浏览各家活动中心** — 每家交易所的活动中心页用 CDP 打开，浏览当前进行中的活动，获取一手信息
2. **WebSearch 补充** — 搜索发现 CDP 浏览中遗漏的活动（如已结束但仍有参考价值的、第三方报道中提到的）
3. **CDP 走用户路径 + 截图** — 对重点活动逐步截图
4. **子 Agent 并行** — 多个交易所分发子 Agent 并行执行上述流程，每个子 Agent 自行 `/new` 创建 tab、操作、`/close` 关闭

> **关键：不要用子 Agent 只做 WebSearch 然后主 Agent 手动 CDP。** 子 Agent 应包含完整的 CDP 浏览+截图流程。

### 交易所实时行情页

CDP 直连真实 Chrome，WebSocket 推送的实时数据（价格、交易量、认购进度等）在页面上直接可见，通过 `/eval` 从 DOM 提取即可。

如需补充数据：第三方聚合站（CoinMarketCap、CoinGecko）的价格页仍可用 WebFetch 或 Jina 快速抓取。

### 地区限制

CDP 使用本地网络 IP。如目标页面有地区限制：
- 先用 CDP 打开确认是否被拦截
- 被拦截时提示用户挂 VPN 切换地区，然后刷新页面继续
- 仍无法访问则标注"地区限制"，不再重试

### 覆盖率要求

采集完成后，入口.md 竞品范围内每家必须为以下之一：
- **有活动**：已采集详情 + 截图
- **确认无活动**：至少两轮搜索无结果，明确标注
- **数据获取失败**：标注原因（反爬/地区限制），列出已尝试路径

## 截图规范

每个有活动的交易所需全路径截图。

### 截图方式

使用 CDP `/screenshot` + curl `-o` 保存：

```bash
curl -s "http://localhost:3456/screenshot?target=ID" -o "{截图目录}/{交易所}_{活动简称}.png"
```

> **注意：** 不要用 `/screenshot?file=` 参数传含中文或空格的路径，会报错。统一用 curl `-o` 输出。

### 用户路径截图

竞品调研的核心场景是走完用户路径并逐步截图：

1. `/new` 打开活动页入口
2. `/screenshot` 截取当前页面
3. `/click` 或 `/eval` 点击下一步（报名、参与、领奖等）
4. `/screenshot` 截取每一步的页面状态
5. 重复直到路径走完

每步截图命名：`{交易所}_{活动简称}_{步骤序号}.png`

### 截图作为数据采集手段

当页面 JS 渲染的数据无法通过文本提取时，截图本身就是数据源：
- 交易所活动页面的认购数据（参与人数、认购进度、超额倍数等）往往只在 JS 渲染的 UI 中展示
- 先截图确认页面有哪些字段，再用 `/eval` 从 DOM 提取具体数值

## 产出结构

### 周报（活动创意调研）— 主要产出格式

所有产出内容均以表格形式输出，不使用自由文本段落。根据内容选择合适的表格式：

#### 格式一：主线总览表（列方向）

按洞察主线组织，适合横向对比多条主线。每条主线占一组列，行结构固定：

| 行 | 说明 |
|------|------|
| **主线标题**（首行） | 跨列标题，如"1. 活动游戏化"、"2. 抽奖换皮"、"3. 参与门槛降低" |
| （案例来源） | 该主线下的典型案例方（如"Binance"、"Bitget"），紧跟标题行下方 |
| **机制** | 活动机制简述（2-3 句，说清核心规则） |
| **关注指标** | 该主线关注的运营指标（如"拉新裂变"、"提升 DAU"） |
| **图例** | **截图直接嵌入此行**，每个案例对应一张活动页截图 |
| **可落地点** | 我方可借鉴的具体行动，可 @负责人 |
| **进度** | 当前跟进状态（"-" 表示未启动，已启动则写进展） |

#### 格式二：活动主线汇总表（行方向）

按洞察主线逐条展开，每条主线占一行。适合主题调研或主线较多时：

| 列 | 说明 |
|------|------|
| **总结** | 活动主线/主题名称（如"Tradfi IPO"、"拼图游戏活动"） |
| **想得到什么** | 帮助运营达成什么共识/价值（如"拉新用户、净入金"、"提升 DAU"） |
| **活动具体内容** | 逐家列出：**交易所名：**[活动名](链接) + 机制简述，多家用换行分隔 |
| **借鉴点** | 可借鉴的核心策略（一句话） |
| **todo项** | 具体跟进事项，可 @负责人 |
| **活动参考图例1** | **截图嵌入**（第一张） |
| **活动参考图例2** | **截图嵌入**（第二张） |

#### 格式三：交易所动向总览表

按交易所维度汇总近期动态，适合周报底部的全景概览：

| 列 | 说明 |
|------|------|
| **交易所** | 交易所名称（Binance、OKX、Bybit 等） |
| **整体动向** | 该交易所近期重要动态链接列表（公告、上线、合作等），每条带超链接，换行分隔 |
| **活动侧** | 与现货运营相关的活动动态链接列表，格式同上 |

#### 要点

- **所有内容在表格内**：分析写在"机制"/"借鉴点"列，行动项写在"可落地点"/"todo项"列，截图嵌入"图例"行/列。不要在表格外另写自由文本段落
- **截图在表格内，不是表格外**：图例行/列的每个单元格放对应案例的活动截图
- **按洞察主线分类，不按交易所分类**：同一主线下聚合多家交易所的案例，横向对比更有价值
- **链接必填**：每个活动案例必须附原始活动链接，无链接标注"链接未获取 — {原因}"
- **活动具体内容格式**：**交易所名加粗** + 活动名带超链接 + 换行后写机制简述，多家之间用换行分隔

### 活动创意调研（主题深挖）

#### 1. 活动结论

横向对比表，每个维度给出最佳实践案例 + 简评：

| 维度 | 关注点 |
|------|--------|
| 准入门槛 | 报名方式、最低交易额、新老用户区分 |
| 社交属性 | 裂变机制、KOL 联动、阵营对决、互赠/分享 |
| 用户触达 | 入口数量、视觉刺激（跑马灯/倒计时/弹窗）、触达频率 |
| 用户留存 | 打卡机制、多期活动、习惯养成设计、LTV 延长策略 |
| 品牌势能 | 活动与品牌形象联动、叙事一致性 |
| 开奖/奖励特色 | 开奖频率、奖品形式（实物/代币/体验金）、确定性 vs 彩票感 |

#### 2. 友商活动概览

逐家深挖，每家统一格式：

| 字段 | 说明 |
|------|------|
| 活动链接 | 原始 URL |
| 活动链路 | 用户从首页到参与的完整路径（入口位置、跳转层级），配逐步截图 |
| 活动机制 | 分活动一/二/...描述规则，含门槛、任务、奖励发放方式 |
| 总奖池 | 金额 + 币种/形式 |
| 时间节点 | 起止时间、是否分期 |
| 活动亮点 | 该活动的核心策略洞察（为什么有效、对用户行为的驱动逻辑） |

每家末尾嵌入截图。

#### 3. 可复用点

分两类输出：

**UI/UX：**
- 视觉刺激元素：中奖名单轮播、开奖倒计时、异型弹窗、奖品估值展示
- 入口设计：有逻辑承接的活动入口就近放置
- 游戏化交互：刮刮乐、盲盒、福卡等

**活动逻辑：**
- 流量承接：活动间的用户流转设计
- 拉新策略：低门槛 / 100% 中奖 / 高频开奖 / 保赔券
- 社交裂变：节日祝福类 / 热点辩论类 / KOL 带队竞赛 / 互赠机制
- 留存设计：每日打卡、多期活动、阶梯任务
- 品牌联动：活动叙事与品牌形象的结合点
- 开奖创新：哈希开奖、实物奖品、阵营对决等差异化形式

### 产品功能调研

#### 1. 数据结论

各家功能横向对比表，维度按主题灵活调整，常见维度：
- 品类数量与覆盖范围
- 费率结构（基础费率、VIP 折扣）
- 规则与门槛
- 收益/APR

#### 2. 梯队分析

按功能深度划分第一/二/三梯队，说明分级依据：
- 第一梯队：全品类覆盖、机制成熟
- 第二梯队：多品类试水、有差异化亮点
- 第三梯队：象征性布局、非战略重点

#### 3. 精进项

结合我方现状，提出可跟进方向（如新品类、费率优化、机制借鉴）。

### 数据快照

适用场景：针对特定产品/事件，快速拉取关键数据点（非全量活动调研）。

#### 1. 核心数据对比表

横向对比各家同一产品的关键指标（参与人数、认购金额、产品机制等）。

#### 2. 实时交易数据

当前价格、24h 量、vs 认购价/发行价。标注数据来源和采集时间。

#### 3. 社媒情绪

正面 / 负面分列，标注来源（Twitter KOL、Reddit、媒体）。

#### 4. 数据缺口说明

标注哪些数据点未获取到、原因、已尝试路径。对未公开数据提供合理推算。

### 竞品基础情报

维护持续更新的对比表，维度：费率结构、拉新机制、VIP体系、现货产品布局。标注每条数据的更新时间。
