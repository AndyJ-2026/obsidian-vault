# 三板斧 Skill 规格

## 1. 定位

Claude Code 的 slash command（`.claude/commands/sanbanfu.md`），让运营团队通过自然语言输入决策命题，AI 自动分析利弊，输出标准三板斧表格，确认后发布到飞书文档。

**触发方式**：`/sanbanfu` 或用户说"做三板斧"、"发起三板斧"、"写三板斧"

## 2. 输入

### 必填信息
| 字段 | 说明 |
|------|------|
| 命题 | 这次要决定什么 |
| 背景介绍 | 为什么提这个命题 |
| 选项 | 3～5 个备选方案（只需描述，利弊由 AI 分析） |

### 可选信息
| 字段 | 说明 | 默认值 |
|------|------|--------|
| 期望结果 | 希望达成什么目标 | 留空 |
| 完成时间 | 何时需要决策 | 留空 |
| 参与成员 | 谁参与投票（第一个为第一责任人） | 留空 |
| 目标文档 | 插入到已有飞书文档的 URL | 新建文档 |

### 输入方式
- **一次性描述**：用户一段话说完命题+背景+选项，AI 自动解析
- **分步引导**：用户只说"做三板斧"但没给内容，AI 逐步询问
- **两种都支持**：用户提供多少就用多少，缺的再问

## 3. 好三板斧的质量标准

> 基于 6 个真实案例（SpaceX上线时机、代币名称、明星项目国家线协作、USD1预算分配、现货活动精进、稳定币方案）的交叉分析，提炼出以下标准。AI 生成内容时必须以此为自检清单。

### 3.1 命题锐利
- **必须是可投票的具体决策**，不是讨论话题
- 好：「确定 SpaceX launchpad 和预热页的上线时间」
- 坏：「讨论 SpaceX 上线安排」
- AI 检查：如果命题太泛，主动帮用户收窄到一个可决策的问题

### 3.2 选项互斥且穷尽（MECE）
- 每个方案是**真正不同的路径**，不是同一思路的微调
- 好：方案1=5月13日上线（无预热）/ 方案2=5月15日上线（带预热）/ 方案3=继续观望 / 方案4=不做
- 坏：方案1=5月13日 / 方案2=5月14日 / 方案3=5月15日（本质上是同一件事的微调）
- AI 检查：选项之间差异度不够时，建议合并或重新划分

### 3.3 背景带数据，不是纯叙事
- 背景中应包含**支撑决策的硬数据**：竞品数据、市场数据、历史数据、成本数据
- 好：「竞品SPAX涨幅超13%，650U认购价具备优势」「币安4000万带动20亿AUM」
- 坏：「最近市场比较热，我们也应该做一下」
- AI 检查：如果背景缺数据，追问「有没有相关的竞品数据/历史数据/成本测算？」

### 3.4 利弊直指决策维度
- 每条利/弊必须回答：**「这条会不会改变投票？」**
- 删掉三类无效条目：
  - **影响力弱的**：选项固有特征不构成利/弊（如"认购窗口仅3天"对限时方案是固有属性）
  - **不可改变的**：已决策事项不构成弊（如"定价650U"已定，不再是弊）
  - **过于泛化的**：「用户体验好」「有一定风险」——必须具体到什么好、什么风险
- 好：「①趁热打铁：CNBC报道（5/9）+OKX新合约（5/6）热度仍在，FOMO情绪未散」
- 坏：「①市场热度高：目前市场关注度比较高」

### 3.5 弊要带解法（重要弊项）
- 真实案例中，关键弊项后面会附带**缓解方案**
- 格式：弊的正文后加换行，**`解法：`** + 一句话方案
- 例：「①需要时间熟悉当地市场：...  解法：运营与当地KOL建立社群，方便了解市场资讯」
- 不是所有弊都需要解法，只对**可缓解且影响决策的弊**附带

## 4. AI 分析能力

### 4.1 信息充分性检查（生成利弊前的前置步骤）

AI 生成利弊前，必须先评估背景信息是否足够。不够就追问，**不要基于不充分的信息硬写**。

需要检查的维度：
| 维度 | 追问示例 |
|------|---------|
| 竞品情况 | 「竞品（Gate/BG/币安）目前在这个领域的做法是？有数据吗？」 |
| 成本/预算 | 「每个方案的预估成本或资源投入有差别吗？」 |
| 时间约束 | 「有没有外部时间节点（市场事件、竞品动作）影响这个决策？」 |
| 内部资源 | 「执行这些方案需要哪些团队配合？有瓶颈吗？」 |
| 历史数据 | 「之前做过类似的事吗？效果怎么样？」 |

用户可以选择不提供，AI 标注为"信息不足"继续生成，但**必须在利弊中体现这个不确定性**。

### 4.2 利弊标注来源

每条利/弊必须区分：
- **[数据]** — 基于用户提供的硬数据（如"CNBC 5/9报道"、"涨幅13%"）
- **[推断]** — AI 基于逻辑推理得出（如"热度可能衰减"）
- **[行业]** — AI 基于行业通识判断（如"破发会损伤品牌口碑"）

标注方式：在终端预览中显示标签，飞书正式版不显示（保持简洁）。
目的：让决策者快速判断哪些利弊可信度高、哪些需要进一步验证。

### 4.3 利弊写作规范
- 每条利/弊固定格式：**`①关键词：`**（加粗）+ 一句话解释（结尾加 `；`）
- 每个方案利弊各 **2～3 条**，严格筛选
- 宁少勿多：2 条真正重要的 > 5 条稀释权重的
- 使用业务语言，不堆技术数据（数据放背景，利弊写业务结论）
- 不确定结果加"可能"/"有可能"
- 利弊之间要有**区分度**：不同方案的利弊不能高度重复

### 4.4 核心方案描述列（复杂情况）
当选项名称无法自解释时，自动在方案列和利列之间插入描述列：
- 加列条件：选项名不足以说清"怎么做"（如"类FTX方案"需补充"用户充值后平台自动转为MUSD"）
- 不加列：选项名已清晰（如"5月15日上线"）

### 4.5 Challenge 模式
AI 不只是被动填表，应主动质疑和补充：
- **选项遗漏**：「有没有考虑过不做/暂缓这个选项？」（真实案例中"方案4=不做"经常出现）
- **利弊盲区**：提示用户可能忽略的风险或优势
- **选项表述优化**：建议更清晰的选项名称
- **背景数据缺口**：如果背景太薄，主动要求补充硬数据
- **MECE 检查**：选项之间有重叠或遗漏时指出

## 5. 输出

### 5.1 终端预览（Step 1）
以 Markdown 表格形式展示完整三板斧，利弊带来源标注：

```markdown
## 三板斧：[命题]

| | |
|---|---|
| **命题** | [内容] |
| **背景** | [内容] |
| **期望结果** | [内容] |
| **完成时间** | [日期] |
| **参与成员** | [名单] |

| 序号 | 建议/选项 | 利 | 弊 |
|------|----------|-----|-----|
| 方案1 | [选项] | ①**关键词：**解释 [数据]；②... | ①**关键词：**解释 [推断]；②... |
| 方案2 | ... | ... | ... |
| 方案3 | ... | ... | ... |
| 其他方案 | | | |
```

展示后：
1. AI 自评：「以上利弊中，X 条基于你提供的数据，Y 条是我的推断。建议重点审核推断部分。」
2. 询问用户：利弊是否准确？有没有我遗漏的内部因素？
3. 确认后发到飞书文档？

### 5.2 发布到飞书文档（Step 2）
用户确认后，执行飞书发布（正式版不含来源标注，保持简洁）：
1. **嵌入模板 sheet**（token: `HqQWscq4WhmyLPtezsGuIE0MsYc`, sheet-id: `HVpAUK`）到目标文档
2. **写入内容**到嵌入后的新 sheet
3. **发送消息**通知用户文档链接

具体操作流程参见 `调研/SKILL-参考.md` 中的执行步骤。

## 6. 标准表格格式

9行 × 5列（复杂情况 9行 × 6列）：

**信息头部（行1-4）**

| A列 | B列 | C列 | D列 | E列 |
|-----|-----|-----|-----|-----|
| 命题 | [内容] | (合并到B) | 参与成员 | [名单] |
| 背景介绍 | [内容] | (合并到B) | (合并到B) | |
| 期望结果 | [内容] | (合并到B) | | |

**选项区域（行5-9）**

| A列 | B列 | C列 | D列 | E列 |

| 序号/提议人 | 建议/选项 | 利 | 弊 | 投票人 |

## 7. 约束

- 投票人列始终留空（由参与者自行填写）
- 利弊由 AI 分析生成，不需要用户提供
- 合并单元格通过嵌入模板 sheet 实现，不手动创建
- 嵌入后使用返回的新 token 操作，不使用原始模板 token
- AI 不能编造数据——没有数据支撑的判断必须标注为推断

## 8. 验收标准

- [ ] `/sanbanfu` 可触发 Skill
- [ ] 支持一次性输入和分步引导两种模式
- [ ] AI 生成利弊前先做信息充分性检查，不够就追问
- [ ] AI 生成的利弊符合写作规范（格式、条数、业务语言）
- [ ] 利弊标注来源（数据/推断/行业），让决策者知道可信度
- [ ] 弊项带解法（重要弊项）
- [ ] AI 能主动 challenge 用户的选项和背景（MECE、数据缺口、遗漏方案）
- [ ] AI 自评推断比例，提示用户重点审核
- [ ] 终端预览格式清晰可读
- [ ] 用户确认后成功嵌入 sheet 到飞书文档
- [ ] sheet 内容正确填充（合并单元格、利弊格式）
- [ ] 发布后发送消息通知用户
