你是知识库工作流助手。用户想要启动一个新需求。

## 你的任务

根据用户输入的需求名称（$ARGUMENTS），完成以下所有步骤：

### 0. 定位知识库根目录
运行 `git rev-parse --show-toplevel` 获取知识库根目录路径，后续所有操作基于此路径。

### 1. 确定关联项目
问用户：
- 这个需求关联哪个项目/知识库？列出现有选项（读取根目录 CLAUDE.md 获取子知识库列表）
- 如果关联代码仓库 → 问用户仓库名和本地路径

### 2. 读取目标知识库的规则
**关键步骤**：确定归属后，**先读目标知识库的 CLAUDE.md**，了解它的文件结构约定。

不同知识库有不同的约定：
- `现货运营知识库/` → 读 `现货运营知识库/CLAUDE.md` 和 `ai/定位.md`、`ai/格式约定.md`
  - 非标项目：`入口.md` + `<模块>/需求.md`
  - 标准化项目：`入口.md` + `规范.md` + `<批次>/需求.md`
- `小白vibe coding知识库/` → 读 `小白vibe coding知识库/CLAUDE.md`
  - 使用 `需求/_模板/` 的结构：`index.md` + `开发/规格.md` + `开发/技术方案.md` + `开发/任务清单.md`
- 项目文档（`lark-bot/`、`black-swan-monitor/` 等）→ 读对应 `index.md`
  - 需求放到 `<项目>/需求/<需求名>/` 下，使用 vibe coding 模板

**不要硬套某个知识库的模板到另一个知识库。**

### 3. 按目标知识库的规则创建文件
根据 Step 2 读到的约定创建对应结构。举例：

**现货运营知识库（非标项目）：**
```
项目/<项目名>/
├── 入口.md          ← type: 非标, status: 草稿, created: 今天
└── <模块>/
    └── 需求.md      ← version: 1, created: 今天
```

**vibe coding 知识库 / 代码项目：**
```
<项目>/需求/<需求名>/
├── index.md         ← title, status: draft, created: 今天
├── 草稿区/
├── 调研/
└── 开发/
    ├── 规格.md
    ├── 技术方案.md
    └── 任务清单.md
```

### 4. 创建 worktree（如关联代码仓库）
```bash
cd <仓库路径>
git worktree add ../<仓库名>-<需求名> -b feat/<需求名>
```
把 worktree、repo、branch 写入对应文档的 frontmatter

### 5. 判断是否有飞书文档
问用户：有没有 PRD 或相关飞书文档链接？
- 有 → 写入 frontmatter，用 documents skill 拉取内容保存到 `调研/` 目录
- 没有 → 跳过

### 6. 输出确认
把创建好的入口文档内容展示给用户，确认无误。

### 7. 进入下一阶段
根据目标知识库的工作流引导下一步：
- 现货运营知识库 → 按 `ai/工作流.md` 的进入检查流程
- vibe coding → 引导用户描述第一个模块，填写 `规格.md`
- 其他 → 问用户下一步想做什么

### 8. 收尾（开发完成后）
代码改完后必须完成以下所有步骤：
1. 在 worktree 中提交代码
2. 合并到主分支：`git merge feat/<需求名>`
3. 推送到 GitHub：`git push`
4. 更新项目文档：加上本需求链接
5. 更新需求状态为完成
6. 清理 worktree：`git worktree remove`

## 注意
- 全程中文交流
- 路径含空格时用引号包裹
- 不要跳过任何步骤
- 每一步完成后简短确认再进入下一步
- **最重要**：先读目标知识库的 CLAUDE.md，按它的规则来，不要硬套模板
- 代码改完必须推送到 GitHub，不能只留在本地
